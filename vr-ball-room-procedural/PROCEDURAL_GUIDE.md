# Procedural guide: how to build on this without starting over

Everything visible in this game is generated by the code in `src/procedural/`. This guide is the
map: what each piece does, the recipe for adding more, how to look at the result, and the traps
that already cost time once. Read it before changing anything.

## Workflow (from the repo root, in WSL)

```bash
tools/build.sh      # typecheck + production build; prints only errors
tools/serve.sh      # (re)start the preview at https://localhost:4173/
tools/views.sh      # screenshot every standard view into tools/out/*.png
tools/views.sh gallery          # only views whose name contains "gallery"
tools/shot.sh name "quality=high&dbg=gallery,bakefast&look=-0.1,-0.9&pos=-301.5,0,1.2"
tools/dump.sh "quality=high&dbg=gallery,bakefast,info"   # one line of state + caught errors
```

Always build, screenshot, and **look at the PNG** before committing. Add a line to
`tools/views.sh` for anything new you build so it stays covered.

URL parameters: `quality=high|low|auto`, `look=pitch,yaw` (radians), `pos=x,y,z` (world metres),
and `dbg=` with any of `night`, `monke`, `gallery` (start in the Gallery), `bakefast` (finish the
light bake in a few frames), `info` (state in the page title, read by `tools/dump.sh`).

## The modules

| File | What it is | Use it for |
|---|---|---|
| `quality.ts` | High / Low tier numbers | Any count or size that should drop on a headset |
| `textures.ts` | Surface shaders rendered to albedo + normal + roughness/metal maps on the GPU | A new surface (wood, stone, cloth...) |
| `materials.ts` | Ready-to-use materials built on those maps | Picking a material: `oak`, `plaster`, `fabric`, `marble`, `rug`, `floorPlanks`, `plastic`, `rubberBall`, `canMetal` |
| `geometry.ts` | Rounded boxes, smooth cylinders/spheres, lathe-turned props (table, cans, pins, bell, darts, car parts) | Modelled props and the drop-in primitives `room.ts` builds from |
| `decor.ts` | Plants, shelves with books/vases/art, rug, LED wall washes, painted corner shadows (main room) | Dressing a room without baked lighting |
| `env.ts` | Sky shader, reflection probe, sun, light shafts, dust, lamps, lighting zones | Anything about light, sky or reflections |
| `bake.ts` | GPU light bake for box-built scenery | Real soft lighting and ambient occlusion |
| `furniture.ts` | Modelled furniture: `pillow()` (rounded, stuffed cushion shape), task chair, floor lamp, sofa cushions, desk accessories | Any furniture: build from `pillow`, lathe profiles and mixed materials, never plain boxes |
| `plants.ts` | Weeping fig grown from a branch skeleton: merged tube mesh for the wood, instanced modelled leaves with a painted vein texture, planter with clay pebbles | Any potted plant (`buildPlant(height, seed, steelPot)`) |
| `stations.ts` | Modelled bodies for the toy stations: hoop frame and rim mount, turned pedestals, xylophone frame, arcade cabinet and marquee, high-striker scale and bulbs, punch-bag, lane markings; `decal()` for printed graphics, `hollow()` to hide a collider mesh | Dressing a gameplay collider as a real object |
| `showcase.ts` | The Gallery room, its doors and its system | The reference for building a baked room |
| `arena.ts` | The outdoor Monke Map | Terrain, trees, rocks, grass |

## Recipes

**New surface texture.** In `textures.ts` add a function that calls `buildSet(size, normalStrength, glsl)`.
The GLSL must define `void surf(vec2 uv, out vec3 c, out float h, out float r, out float m)`:
colour (sRGB 0-1), height (drives the normal map), roughness, metalness. Helpers available:
`ih` (hash), `vnoise`, `fbm` (both tile when given the lattice period), `cells`. Then add a
material function in `materials.ts` that caches the set and calls `withSet`.

**New box-built scenery with baked light** (walls, furniture, shelves): see `buildShowcase`.
`B(material, x0, y0, z0, x1, y1, z1, { albedo, emissive, uv })` adds a box that both renders and
takes part in the bake. `albedo` is the colour bounced light picks up; `emissive` makes it a lamp;
`uv` is metres of surface per texture repeat. Leave openings as gaps between boxes: that is how
sky light gets in. Curved props are ordinary meshes added to the group; give them a rough
`bake.addOccluder(min, max, albedo, [0,0,0])` box so they cast soft shadow.

**New modelled furniture.** Add a function to `furniture.ts` that returns a `Group` standing on
y = 0. Use `pillow(w, h, d, radius, puff)` for anything upholstered or soft-edged, `lathe()` for
turned or round parts, and a different material per real-world material. In the room: position it,
add it to the props group, call `bake.bakeObject(group)` so it gets baked light, and add one or two
rough `bake.addOccluder` boxes so it shadows the floor and walls. Do not share its materials with
unbaked meshes.

**New room.** Copy the shape of `showcase.ts`: build with a `LightBake`, add invisible
`PlainBox` proxies with `LocomotionEnvironment` for walking, define an `EnvZone` (probe position,
room box, sun target) and call `procEnv.setZone(zone)` while the player is inside.

**New prop in the main room.** Build a mesh/group and add it to `procEnv.roomGroup` (it is hidden
automatically in the Monke Map). Thrown objects need a `PhysicsShape` + `PhysicsBody`; see `room.ts`.

**Dressing a gameplay block.** Keep the `staticBox` collider, call `hollow(entity.object3D)` so it
draws nothing, and add a modelled group from `stations.ts` as its child (origin = collider centre).
Printed graphics (scales, signs, markings) are `decal()` planes painted on a canvas.

## Traps (each of these has already bitten once)

- **Headless screenshots render only a handful of frames**, whatever the time budget. Effects that
  settle over many frames look unfinished: use `dbg=bakefast`, and treat "night"/"monke" views
  with suspicion if they look half-applied. `tools/dump.sh` tells you the real state.
- **One `onBeforeCompile` per material.** `env.ts` (box-projected reflections), `bake.ts` and the
  wind shaders each install one. To combine, call the other hook from yours (as `bake.ts` does
  with `boxCompile`) and set `userData.noBoxProject = true`.
- **The engine re-aims the sun every frame** from its entity's transform. Move the light with
  `placeLight` in `env.ts` (it moves the whole entity); do not set `light.position` yourself.
- **GLSL reserved words** (`patch`, `sample`, `filter`, `input`, `output`...) fail the shader
  compile with no visible error on screen. `tools/shot.sh` prints shader errors: read its output.
- **Import Three.js classes from `@iwsdk/core`**, never from `three` (a second copy breaks things).
- **Geometry the Monke Map collides with must be baked into world coordinates** (identity
  transform); materials whose name starts with `leaves` are skipped by collision.
- **`retile()` clones share one GPU upload**; do not free texture data after upload.
- Bake cost grows with (vertices x rays x boxes). Keep box counts in the hundreds and use the
  `spacing` option on long thin boxes.
- Never stop the preview with `pkill -f <pattern>` from a command line that contains the pattern;
  `tools/serve.sh` kills by port instead.

## What is honest about the lighting

- The Gallery's indirect light, lamp light and ambient occlusion are computed (ray traced on the
  GPU against boxes) and stored per vertex. Direct sun is real-time shadow mapping.
- The main room is not baked: its corner shadows and LED washes are painted gradients, and its
  bounce light comes from the reflection probe.
- There is no post-processing (bloom, depth of field), because the engine owns the render loop.
